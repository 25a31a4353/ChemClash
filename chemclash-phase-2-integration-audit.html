🔴 Critical Issues

CRITICAL 1 Dashboard stats bar is entirely hardcoded — never reflects real data
The four stat tiles (REACTIONS ATTEMPTED: 248, ACCURACY RATE: 73%, BEST STREAK: 12d, GLOBAL RANK: #84) and the hero subtitle ("Top 12% globally") are all static constants in page.tsx lines 205–210. The store does hydrate real eloRating and dailyStreak from the backend but those values are never used in the STATS array. A demo evaluator will see values that never change, breaking the illusion that the app is data-driven. The eloRating from Zustand is shown in the TopNav and hero text — but the stat cards below it always show "248 / 73% / 12d / #84" regardless of what the backend says.
CRITICAL 2 Adaptive PYQ is marked locked: true on the Dashboard card but is the primary recommendation target everywhere else
In page.tsx line 129, adaptive-pyq game-mode card has locked: true and badge: "COMING SOON". However, the "Recommended for You" panel, the Duel result screen's "Review Videos" CTA, every Tutor Shorts card's practice button, Video Recommendations' footer link, the Skill Tree nodes med_02 / med_03 / med_04 / adv_01 / adv_03, and the Rewards Shop all link to /adaptive-pyq. The page itself works correctly — the inconsistency is that the Dashboard card says "COMING SOON / LOCKED" while nine other places invite the user to click it. During a live demo this will confuse evaluators immediately.
CRITICAL 3 /resources page exists as a route but is completely missing from the Dashboard game-mode grid
chemclash/src/app/resources/page.tsx exists and is personalised (reads top_weaknesses from the store). It is not listed in the GAME_MODES array at all, so there is no card, no link, and no way to reach it from the Dashboard via normal navigation. A user or evaluator has no discoverability path to it unless they type the URL manually.

🟠 Important Issues

IMPORTANT 1 Dashboard's loadPlayerProfile is never called — streak and username stay at defaults on page load
The Dashboard useEffect (line 392–395) calls claimLoginReward() and refreshProfile() but not loadPlayerProfile(). refreshProfile fetches the adaptive weakness profile (/api/adaptive/profile/{id}) to populate profile.top_weaknesses. loadPlayerProfile fetches the game profile (/user/{id}) to hydrate eloRating and dailyStreak into the store. So on the Dashboard, streak_days remains 0 and username shows the raw UUID (the anonymous ID) rather than any server-side label. The TopNav and hero will display the UUID as the welcome message until the user navigates to Adaptive PYQ (which calls startSession, which calls loadPlayerProfile).
IMPORTANT 2 Duel (Practice Arena) result screen shows missed concepts but the "Review Videos" CTA does NOT pre-filter the video page
After a Duel match, ArenaResult (line 559–566) shows a "Review Videos for Missed Concepts" link that navigates to /video-recommendations. That page reads profile.top_weaknesses from the Zustand store — but the Duel's processAnswer calls syncMatchResult (fire-and-forget to /user/{id}/update-match) which intentionally does not update concept_weaknesses in the canonical user_profiles.py store (by design, line 182–183 of user.py). Only POST /api/adaptive/answer updates weakness scores. So the video recommendations shown after a Duel reflect old weakness data, not the concepts just missed in that match, breaking the stated "personalised" promise at a critical demo moment.
IMPORTANT 3 Skill Tree mastery key mismatch — Curriculum writes bas_01… IDs, but Skill Tree nodes don't map to actual Curriculum module_ids
curriculum/page.tsx writes localStorage.setItem(LS_MODULE_KEY(selectedModule.module_id), "1") using the backend's module_id values (e.g. "basics_sn1", "advanced_eas" from concept_tree.json). The Skill Tree reads LS_MODULE_KEY(node.id) for its own static node IDs ("bas_01", "med_03", etc.). These IDs will never match unless the backend's module_ids happen to equal the Skill Tree node IDs — which they don't. Result: completing a Curriculum module never marks the corresponding Skill Tree node as Mastered. The Mastery flow is broken at the last step.
IMPORTANT 4 Leaderboard is entirely static mock data — ELO shown in "My Position" is live but the board itself is fabricated
leaderboard/page.tsx lines 13–37 define hardcoded arrays GLOBAL_BOARD and WEEKLY_BOARD with fictional usernames. The "My Position" row reads from the Zustand store (eloRating, username) so it is live, but it is injected at a hardcoded rank (84 global, 5 weekly). There is no API call to /user/… or any endpoint. For a demo this is fine as a placeholder, but the "LIVE" badge on the dashboard card is misleading — a quick evaluator may ask the backend for leaderboard data and find no such endpoint exists.

🟡 Minor Issues

MINOR 1 "Reaction Pathway Lab" dashboard card (id pathway-lab) points to /mechanism-builder
The card at line 108 has a distinct identity ("LEVEL 2.5", "NEW" badge) but routes to the same /mechanism-builder page as the "Mechanism Builder" card above it. There is no dedicated /reaction-pathway-lab route. Evaluators may click it expecting a different experience and get the same canvas. Either merge the cards or create a distinct route.
MINOR 2 Rewards Shop purchases have no actual effect — "unlock" is cosmetic only
Purchasing a reward in rewards/page.tsx deducts ChemCoins and stores the reward ID in localStorage, then shows a "✅ Open [page] →" link. However the linked pages (Adaptive PYQ, Tutor Shorts, etc.) have no awareness of which rewards were purchased. There is no "SN2 filter active" state passed to those pages. The reward descriptions promise "unlocks a focused run of SN2 questions" or "activates a bonus Tutor Shorts session filtered to EAS" but the destination pages always start in their default state. This is a demo gap but not a crash.
MINOR 3 Weekly Activity chart is hardcoded static data
ACTIVITY = [40, 70, 55, 90, 65, 80, 100] at line 212 is never populated from the backend. The chart always shows the same 7-bar pattern regardless of whether the user has ever played.
MINOR 4 Snap-to-Solve gracefully degrades to supported: false when vision not configured, but the UI state for that case was not verified to be polished
The backend correctly returns {"supported": false, "reason": "…"} when OPENAI_API_KEY is absent or the model is not vision-capable. The frontend (line 17–21 of the API client) types SnapResponse = SnapResult | SnapUnsupported. As long as snap-to-solve/page.tsx renders the reason text clearly, this is fine — but it means the feature shows as partially broken in any demo environment without a valid GPT-4o key.
MINOR 5 Tutor Shorts concept filter does not include markovnikov / leaving_group / carbonyl / aromaticity tags in the weakness-priority sort
The weakness sort in tutor-shorts/page.tsx (line 356–361) matches short.conceptTag against topWeaknesses from the backend. The backend's get_top_weaknesses returns raw concept tags from pyq_db.json (e.g. "steric_hindrance", "leaving_group"). Several Tutor Shorts use tags like "markovnikov", "leaving_group", and "carbonyl" which exist in both datasets — these will surface correctly. However the VIDEO_MAP in video-recommendations/page.tsx normalises tags with replace(/[^a-z0-9_]/g, "_"), potentially mangling tags with spaces (e.g. "carbocation shifts" becomes "carbocation_shifts") while the CONCEPT_ROUTE_MAP on the dashboard uses the raw string with a space. Low-probability but produces a missed weakness match.

Weakness-matching shorts surface first; weakness filter buttons are highlighted in red; each card's "Practice CTA" links to Adaptive PYQ — Learn → Practice loop is closed.
✅Weakness data drives Video Recommendations
refreshProfile() called on mount; weakness tags map to curated YouTube search URLs with partial-match fallback; foundational cards fill gaps; footer links to Adaptive PYQ. Full Learn → Watch → Practice loop present.

Correct answers award +5 ELO; module completion awards +20 ELO; LS_MODULE_KEY(module_id) is written to localStorage. The Skill Tree reads the same key pattern — the only bug is the ID mismatch (Critical 3 above).

Lobby → match → result flow works; countdown timer auto-expires with wrong answer; per-question ELO tracked; syncMatchResult fire-and-forget; global Zustand ELO updated on match complete.
✅React-or-Reject — backend challenge bank integration
Fetches challenges from /api/challenges; graceful fallback if backend unreachable (uses static seed). Swipe mechanic, feedback overlay, and ELO award all functional.
✅Mechanism Builder — canvas arrow drawing + backend evaluation
SVG drag-to-draw arrows, evaluateMechanism call to /api/evaluate-mechanism, Socratic hint stream via SSE from /api/hint/stream all wired correctly. Falls back gracefully if LLM unavailable.
✅Daily Missions — ChemCoins earn, persist, and display consistently
Login reward auto-claimed on Dashboard mount; Daily Challenge claimable once per day; coin balance persisted in localStorage; Rewards Shop reads same key; deduct-on-purchase logic guards against overspending.
✅ELO propagates across all game modes into the Zustand store
Adaptive PYQ (+10/-5), Curriculum (+5/+20), Duel (+12/-6), all update useChemStore.eloRating correctly and show live in every page's top bar.
✅Skill Tree — lock/unlock logic correct; available/mastered rendering works
Tier-unlock rules (any Tier N-1 mastered → Tier N available) are implemented correctly; click-through CTAs to correct destinations per node type. Only broken by the ID mismatch with Curriculum (Critical 3).
✅Backend adaptive algorithm correctly uses weakness profile
get_top_weaknesses feeds _filter_by_tags which scores questions by tag overlap; difficulty calibration by accuracy; LLM pick with rule-based fallback; hallucination-proof ID validation. Accuracy-based difficulty ordering (easy for <40%, hard for >70%) implemented.
✅All 14 feature pages have a ← Dashboard breadcrumb link
Every feature page has a sticky top nav with a working Link href="/". No page is a dead end.
✅Anonymous persistent user ID across sessions
getAnonId() generates a UUID once and persists it in localStorage. All API calls use this stable ID so weakness profiles, ELO, and streaks accumulate correctly across browser sessions without login.
