1 — Project Architecture

ChemClash is a full-stack, AI-powered organic chemistry platform split into two independently deployable layers:

  • Backend — Python FastAPI + uvicorn served from backend/, deployable to Render.
  • Frontend — Next.js 16 / React 19 app in chemclash/, deployable to Vercel.
  • Root utilities — main.py (unified launcher), generate_db.py (data generator), sync_concepts.py (data sync), shared JSON data files.

Unified dev launcher. Single-command entry point to start backend (uvicorn) and/or frontend (npm run dev) as subprocesses.
  • Modes: --backend, --frontend, --check, default = both
  • Pre-flight checks: Python version ≥3.9, pip packages, Node/npm presence, node_modules, .env file presence & placeholder key warning

FastAPI application — single-file entry point. This is the primary backend file. All logic is intentionally colocated here so any hosting service can point at a single file.

  • MongoDB (Section 14): motor async client for persistent user profiles + ELO; connects to MONGO_URI env var
  • All 15 API endpoints defined here — also partially duplicated in routers/

LLM abstraction layer. Provides a unified evaluate_move(source, target) function that dispatches to either OpenAI or watsonx.ai based on LLM_PROVIDER.

backend/fast_validator.py Python 5.1 KB · 133 lines
Rule-based fast-path validator. Evaluates nucleophile→target pairs in <1ms with no LLM call. Returns a Verdict dataclass or None (LLM fallback).
  • Rule 1: Non-nucleophile source → instant fail
  • Rule 2: Strong nucleophile + tertiary carbon → SN2 steric fail
  • Rule 3: Strong nucleophile + primary/leaving group → SN2 pass
  • Rule 4: Any nucleophile + secondary carbon → pass with E2 warning
  • Rule 5: Any nucleophile + aromatic target → fail (EAS required)
  • Used by: routers/mechanism.py; ⚠ duplicated inline in backend/main.py

6 — Key Findings & Issues

🔴 CRITICAL — user_router not mounted

routers/user.py defines user_router (the MongoDB ELO/streak endpoints) but backend/main.py has no app.include_router(user_router) call. The /user/{user_id} and /user/{user_id}/update-match endpoints are unreachable. The HEAD commit (a9f8dec "hookup MongoDB for UserProfiles") added the router file but did not complete the wiring.

🔴 CRITICAL — Logic duplicated across main.py and routers/

backend/main.py contains inline copies of: the fast validator (Sections 2), challenge bank (Section 3), user profiles (Section 4), LLM chat helpers (Section 7), and all route handlers (Sections 11–13). The routers/ directory holds the same logic in separated, well-structured modules. The two are not properly integrated — it is unclear which set of routes is actually active, creating maintenance risk and potential duplicate registrations.

🟡 WARN — Tests expect 502/503 but implementation returns 200

test_mechanism.py has tests asserting HTTP 502 (LLM parse error) and 503 (service error) status codes. The current routers/mechanism.py catches all exceptions and returns a safe-default 200 pass response, so these tests will fail. The test expectations no longer match the implementation's error-handling strategy.

🟡 WARN — gamification.js not wired into the UI

The well-written, well-tested calculateELO() function in gamification.js is not used anywhere in the app. useChemStore.ts uses a hardcoded ±10/±5 delta instead. The gamification engine is effectively dead code despite having unit tests.

🟡 WARN — Curriculum page disconnected from backend API

curriculum/page.tsx has 30+ modules hardcoded inline as a MODULES[] constant. The backend has a full curriculum API at /api/curriculum/modules serving from concept_tree.json. The frontend never fetches from it, meaning curriculum content is duplicated and changes in the backend data won't reflect in the UI.

🟡 WARN — React-or-Reject not connected to challenge_bank API

react-or-reject/page.tsx uses 15 hardcoded CARDS[] inline and never calls /api/challenges. The backend's challenge bank (8 puzzles) is only used by the Mechanism Builder. The two datasets are different and maintained separately.

🟡 WARN — DownloadCheatSheet.tsx is dead code

chemclash/src/components/DownloadCheatSheet.tsx is not imported or used anywhere in the current codebase. It was superseded by the more complete CheatSheetDownloader.tsx. Should be removed to reduce maintenance surface.

🟡 WARN — Leaderboard uses only mock data

leaderboard/page.tsx displays two hardcoded arrays of 10 players each. No backend endpoint or MongoDB query feeds real data. The current user's ELO is injected from the Zustand store (itself a hardcoded default), so the "LIVE" badge on the dashboard card is misleading.

🟡 WARN — root requirements.txt includes unused streamlit

The root-level requirements.txt lists streamlit>=1.35.0 — a leftover from the Streamlit frontend that was removed in commit 384e2b7. The backend's own backend/requirements.txt correctly omits it. This may cause unnecessary large installs on Streamlit Cloud or CI environments that use the root file.

🟡 WARN — README references wrong launcher file

The quick-start guide says python start.py but the actual launcher is python main.py. start.py does not exist.

🟡 WARN — backend/.env tracked in git

backend/.env is committed to the repository. Although it contains only placeholder values (same content as .env.example), the root .gitignore only excludes .env at root level, not backend/.env. This pattern risks a future real key being committed if a developer edits the file in-place.

🟡 WARN — Data files duplicated across root and frontend

chem_master_data.json and organic_db.json each exist in two places: the repo root AND chemclash/src/data/. They are kept in sync by scripts but divergence is possible if one copy is edited manually. The root copies serve no runtime purpose (neither the FastAPI backend nor the Next.js frontend reads from root).

🟢 GOOD — Hallucination-proof adaptive PYQ

The LLM matchmaker in routers/adaptive.py is well-designed: it only passes a pre-filtered subset of real question IDs to the LLM, validates the returned ID against the candidate set, and falls back to a deterministic rule-based picker if the LLM returns anything invalid. No hallucinated questions can reach the user.

🟢 GOOD — Rule-based fast-path validator

fast_validator.py covers the most common undergraduate mechanism scenarios in <1ms with no API key required. The LLM is only called when no rule fires, making the mechanism evaluator fully usable offline and cost-free for most interactions.

🟢 GOOD — Prefetch queue for instant round transitions

useChemStore.ts maintains a 2-item prefetch queue that is replenished in the background after each answer. Switching to the next question is instantaneous from the user's perspective — no spinner on round transitions.
